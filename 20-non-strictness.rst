惰性求值、WHNF 与性能剖析（Profiling）
================================================================================

Haskell 最显著的语言特征是其默认的\ **非严格求值策略**\ （通常称为\ **惰性求值**\ ，Lazy Evaluation）。它既赋予了我们处理无限数据流、解耦算法生成与消费的超能力，也在某些场景下给初学者带来了“空间泄漏”（Space Leak）的困扰。

深入理解内存中的 Thunk、求值范式以及 GHC 提供的性能剖析工具，是编写工业级高性能 Haskell 程序的必修课。

按需调用与图共享机制
--------------------------------------------------------------------------------

传统的严格求值语言（如 C、Go、Python）采用“按值调用”（Call by Value）：函数参数在传入前必须被\ **全部提前求值**\ 。

而在 Haskell 的按需调用（Call by Need）模型中：

1. **Thunk（悬挂闭包）**\ ：在表达式真正被需要之前，它仅以一个占据极小堆空间的引用闭包（Thunk）形式存在。
2. **图共享（Graph Sharing）**\ ：Thunk 一旦在任何位置首次被求值，其内存单元会被最终结果\ **就地覆盖（Overwrite）**\ 。后续所有对该变量的引用都会直接读取已计算的值，绝不重复计算。

求值范式深度辨析：WHNF vs NF
--------------------------------------------------------------------------------

弱顶层范式（Weak Head Normal Form，WHNF）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

当表达式的最外层已经被求值为\ **数据构造器**\ 或 **Lambda 抽象** 时，该表达式即达到了 WHNF。其内部包含的嵌套字段可以依然是未求值的 Thunk：

.. code:: text

   -- 处于 WHNF 的形态示例：
   (1 + 1, 2 + 2)       -- 最外层是元组构造器 (,)，内部表达式未求值
   Just (take 5 [1..])  -- 最外层是数据构造器 Just
   \x -> x * 2          -- 最外层是函数抽象
   1 : [2 + 3, 4 + 5]   -- 最外层是列表构造符 (:)

完全范式（Normal Form，NF）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

表达式被彻底递归计算到底，内部不再包含任何未求值的 Thunk。例如整数 ``42``\ ，或者内部每个元素都完全求值的列表 ``[1, 2, 3]``\ 。

严格性控制工具箱
--------------------------------------------------------------------------------

当我们在循环累加中不需要保留 Thunk 历史时，可以使用以下手段主动引入严格求值：

1. seq 与严格应用符 ($!)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``seq`` 强制先将第一个参数求值至 **WHNF**\ ，然后再返回第二个参数：

.. code:: haskell

   seq :: a -> b -> b

``$!`` 是结合了 ``seq`` 的严格函数应用操作符：

.. code:: haskell

   f $! x = x `seq` f x

2. 深度严格求值：Control.DeepSeq 与 ($!!)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``seq`` 仅求值至 WHNF，如果一个复杂数据结构内部嵌套了深层 Thunk，``seq`` 是无能为力的。此时可以使用 ``Control.DeepSeq`` 模块的 ``deepseq`` 与 ``$!!``\ ，它通过 ``NFData`` 类型类将整个数据结构\ **彻底递归求值至完全范式（NF）**\ ：

.. code:: haskell

   import Control.DeepSeq

   -- 强制将深层嵌套结构彻底计算展开：
   forcedResult = deepseq myList "计算彻底完成"

3. BangPatterns 语言扩展与严格字段
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

在函数参数或记录字段前添加感叹号 ``!``\ ，指示编译器在进入函数体或构造数据时立即将其求值到 WHNF：

.. code:: haskell

   {-# LANGUAGE BangPatterns #-}

   -- 严格累加器，杜绝空间泄漏
   sumStrict :: Num a => a -> [a] -> a
   sumStrict !acc []     = acc
   sumStrict !acc (x:xs) = sumStrict (acc + x) xs

性能剖析与空间泄漏定位（Profiling 实战）
--------------------------------------------------------------------------------

当程序内存占用异常上升时，GHC 自带的性能剖析工具链能够直接定位问题根源。

第一步：开启性能剖析编译
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

使用 ``-prof`` 与 ``-fprof-auto`` 编译源程序：

.. code:: sh

   $ ghc -prof -fprof-auto -rtsopts Main.hs -o myprog

- ``-prof``\ ：开启性能分析收集。
- ``-fprof-auto``\ ：自动在所有顶层绑定处插入分析成本中心（Cost Centres）。
- ``-rtsopts``\ ：允许在运行时通过 ``+RTS`` 向程序传递运行时管理参数。

第二步：生成运行时间与分配报告
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

执行二进制程序并附带 RTS 参数：

.. code:: sh

   $ ./myprog +RTS -p

程序运行结束后，会在同目录下生成 ``myprog.prof`` 文本文件。打开该文件，你可以清晰看到每个函数所占用的\ **CPU 时间百分比**\ 与\ **内存分配总量**\ ，一目了然定位性能热点。

第三步：生成堆内存走势图（定位空间泄漏）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

通过 ``-hc`` 参数按成本中心采样堆内存：

.. code:: sh

   $ ./myprog +RTS -hc -p

运行完毕后会生成 ``myprog.hp`` 文件。使用 GHC 自带的 ``hp2ps`` 工具将其转换为可查看的 PostScript 矢量图：

.. code:: sh

   $ hp2ps -e8in -c myprog.hp

查看生成的 ``myprog.ps``\ ：

- **健康的堆内存**\ ：呈现平稳规律的锯齿波状（垃圾回收器及时回收无用内存）。
- **存在空间泄漏的堆内存**\ ：呈现一条持续陡峭上升的斜坡状山峰。图表下方会明确标注是哪一个函数在不断堆积 Thunk，为你提供极度精准的修复线索。

小结
--------------------------------------------------------------------------------

- Haskell 采用按需调用与图共享机制，表达式只在被需要时计算一次并就地覆写。
- WHNF 仅展开外层构造器，NF 彻底展开所有深层子项。
- 善用 ``seq``\ 、\ ``$!``\ 、\ ``deepseq`` 与 ``BangPatterns`` 精准控制严格性，防范空间泄漏。
- GHC 的 Profiling 工具链（``-prof``\ 、\ ``+RTS -p``\ 、\ ``-hc``\ ）为高吞吐、低内存系统的性能调优提供了最坚实的工程依据。
