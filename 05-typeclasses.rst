类型类（Typeclasses）
================================================================================

在面向对象语言中，多态通常依赖类继承（Inheritance）或接口（Interface）。而在 Haskell 中，实现“对不同类型提供统一操作契约”的机制是\ **类型类（Typeclasses）**\ 。

什么是类型类？
--------------------------------------------------------------------------------

类型类定义了一组函数签名，代表某种\ **行为契约**\ 。只要一个具体类型实现了这些函数，该类型就成为了该类型类的一个\ **实例（Instance）**\ 。

与面向对象接口的核心区别
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

1. **非侵入式解耦**\ ：在传统面向对象语言中，一个类必须在声明自身时显式写明 ``implements Interface``\ 。而在 Haskell 中，类型定义与其类型类实例是完全分离的。你可以为第三方库乃至系统内置类型随时补充实现新的类型类实例。
2. **静态单态化与内联派发**\ ：Haskell 的类型类在编译期直接由编译器解析，通常在优化后直接内联消除，没有面向对象虚函数表（vtable）的运行时指针跳转开销。
3. **支持多参数与类型关系建模**\ ：不仅能对返回值类型做约束，还能表达多类型之间的代数映射关系。

标准库核心类型类继承图谱
--------------------------------------------------------------------------------

Haskell 标准库中的类型类构成了层级清晰的依赖继承树：

.. code:: text

   Eq (等价比较)
    └── Ord (全序大小比较)

   Num (基础算术: +, -, *)
    ├── Real (可转为有理数)
    │    └── Integral (整除与余数: div, mod, toInteger)
    │         ├── Int (机器字长定长整型)
    │         └── Integer (大数任意精度整型)
    └── Fractional (实数除法: /, fromRational)
         ├── Float (单精度浮点)
         ├── Double (双精度浮点)
         └── Floating (初等超越函数: sin, cos, exp, sqrt, log)

核心内置类型类详解
--------------------------------------------------------------------------------

Eq（等价性）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

提供相等比较 ``(==)`` 与不等比较 ``(/=)``\ ：

.. code:: haskell

   class Eq a where
     (==) :: a -> a -> Bool
     (/=) :: a -> a -> Bool

Ord（全序比较）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

继承自 ``Eq``\ ，提供大小比较。除了 ``<``\ 、\ ``<=``\ 、\ ``>``\ 、\ ``>=``\ ，最核心的原语是三态比较函数 ``compare``\ ：

.. code:: text

   ghci> compare 5 10
   LT
   ghci> compare 10 10
   EQ
   ghci> compare 15 10
   GT

Num 与数值家族
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- ``Num``\ ：提供加减乘以及取绝对值 ``abs``\ 、取符号 ``signum`` 与整数字面量装载 ``fromInteger``\ 。
- ``Integral``\ ：提供整数专有的整除 ``div`` 与取模 ``mod``\ 。
- ``Fractional``\ ：提供真除法运算符 ``(/)``\ 。

Show 与 Read
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- ``Show``\ ：提供 ``show :: Show a => a -> String``\ ，将数据转换为字符串表示。
- ``Read``\ ：提供 ``read :: Read a => String -> a``\ ，从文本反序列化为具体数据。

.. code:: text

   ghci> show (12, True)
   "(12,True)"
   ghci> read "42" :: Int
   42

相互默认实现与最小完整定义
--------------------------------------------------------------------------------

观察 ``Eq`` 类型类的源码定义：

.. code:: haskell

   class Eq a where
     (==), (/=) :: a -> a -> Bool
     x == y = not (x /= y)
     x /= y = not (x == y)

``(==)`` 与 ``(/=)`` 在定义时是\ **相互依赖**\ 的！这意味着在手动编写实例时，你只需要实现其中任意一个，另一个就会自动推导生效。

在 GHCi 中使用 ``:i`` 命令可以查看任何类型类的\ **最小完整定义（Minimal Complete Definition）**\ ：

.. code:: text

   ghci> :i Eq
   class Eq a where
     (==) :: a -> a -> Bool
     (/=) :: a -> a -> Bool
     {-# MINIMAL (==) | (/=) #-}

符号 ``(==) | (/=)`` 表明：只需提供 ``(==)`` 或 ``(/=)`` 其中之一即可构成合法实例。

手动编写类型类实例
--------------------------------------------------------------------------------

定义温度类型并手动定义判等逻辑：

.. code:: haskell

   data Temperature
     = Celsius Double
     | Fahrenheit Double
     deriving (Show)

   instance Eq Temperature where
     (Celsius c1)    == (Celsius c2)    = c1 == c2
     (Fahrenheit f1) == (Fahrenheit f2) = f1 == f2
     (Celsius c)     == (Fahrenheit f)  = c == (f - 32) * 5 / 9
     (Fahrenheit f)  == (Celsius c)     = (Celsius c) == (Fahrenheit f)

测试我们的跨温标判等实例：

.. code:: text

   ghci> Celsius 0 == Fahrenheit 32
   True
   ghci> Celsius 100 == Fahrenheit 212
   True

派生机制（Deriving）与进阶扩展
--------------------------------------------------------------------------------

基本派生
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

对于标准类型类，通常无需手写样板代码，直接在数据类型后追加 ``deriving``\ ：

.. code:: haskell

   data Priority = Low | Medium | High
     deriving (Eq, Ord, Show, Read, Enum, Bounded)

只需一行，\ ``Priority`` 即可直接排序、打印和遍历：

.. code:: text

   ghci> Low < High
   True
   ghci> [Low .. High]
   [Low,Medium,High]

泛化 newtype 派生（GeneralizedNewtypeDeriving）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

在工程中，如果我们用 ``newtype`` 包装了一个底层类型，我们往往希望它自动继承底层类型的所有能力，而不必手写重复代码。

开启 GHC 语言扩展：

.. code:: haskell

   {-# LANGUAGE GeneralizedNewtypeDeriving #-}

   newtype Score = Score Int
     deriving (Eq, Ord, Show, Num)

开启该扩展后，即便 ``Num`` 并不是标准可自动派生的类型类，编译器也能将底层 ``Int`` 的 ``Num`` 能力\ **零开销自动穿透赋予** ``Score``\ ：

.. code:: text

   ghci> Score 80 + Score 15
   Score 95

孤儿实例（Orphan Instances）防范准则
--------------------------------------------------------------------------------

如果一个实例的类型类 ``C`` 与目标数据类型 ``T`` 均不在当前模块中定义，那么在该模块中编写 ``instance C T where`` 就构成了\ **孤儿实例**\ 。

- **危害**\ ：当第三方模块导入你的代码时，会暗中带来潜在的全局实例冲突，破坏编译推导的确定性。
- **最佳实践**\ ：始终保证类型类实例编写在\ **定义该类型类的模块**\ 或\ **定义该数据类型的模块**\ 中。如果实在需要为外部类型补充外部实例，建议先用 ``newtype`` 进行本地包装。
