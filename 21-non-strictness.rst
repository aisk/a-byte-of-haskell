惰性求值、WHNF 与性能剖析（Profiling）
================================================================================

Haskell 最显著的语言特征是默认的\ **非严格求值**\ （通常称为\ **惰性求值**\ ，Lazy Evaluation）。它让我们可以处理无限数据流、把算法的生成和消费分开写，也会在某些场景下带来"空间泄漏"（Space Leak）的问题。

理解 Thunk、求值范式，以及 GHC 提供的性能剖析工具，是写出内存表现可控的 Haskell 程序的前提。

按需调用与共享
--------------------------------------------------------------------------------

严格求值的语言（如 C、Go、Python）采用"按值调用"（Call by Value）：函数参数在传入前必须先求值。

Haskell 采用按需调用（Call by Need）：

1. **Thunk**\ ：表达式在真正被需要之前，只以一个未求值的闭包（Thunk）形式存在于堆上。
2. **共享（Sharing）**\ ：Thunk 一旦被首次求值，其内存单元会被结果\ **就地覆盖**\ 。之后对同一个值的引用直接读取结果，不会重复计算。

以 ``let x = expensive 10 in x + x`` 为例，\ ``x`` 在堆上只有一个 Thunk，两处引用指向同一个位置：

.. mermaid::

   graph LR
     subgraph before["求值前"]
       P1["x + x<br/>左操作数"] --> T["Thunk<br/>expensive 10"]
       P2["x + x<br/>右操作数"] --> T
     end
     subgraph after["求值后"]
       Q1["x + x<br/>左操作数"] --> V["已求值<br/>42"]
       Q2["x + x<br/>右操作数"] --> V
     end
     before -. "第一次需要 x 时求值<br/>并覆盖 Thunk" .-> after

``expensive 10`` 只会执行一次，第二次读取 ``x`` 时直接拿到已经算好的 ``42``\ 。

WHNF 与 NF
--------------------------------------------------------------------------------

弱头范式（Weak Head Normal Form，WHNF）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

当表达式的最外层已经求值为\ **数据构造器**\ 或 **Lambda 抽象** 时，该表达式就处于 WHNF。内部的字段可以仍然是未求值的 Thunk：

.. code:: text

   -- 处于 WHNF 的例子：
   (1 + 1, 2 + 2)       -- 最外层是元组构造器 (,)，内部表达式未求值
   Just (take 5 [1..])  -- 最外层是数据构造器 Just
   \x -> x * 2          -- 最外层是函数抽象
   1 : [2 + 3, 4 + 5]   -- 最外层是列表构造符 (:)

范式（Normal Form，NF）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

表达式被递归求值到底，内部不再包含任何 Thunk。例如整数 ``42``\ ，或者每个元素都已求值的列表 ``[1, 2, 3]``\ 。

严格性控制
--------------------------------------------------------------------------------

在循环累加等不需要保留 Thunk 的场景，可以用以下手段主动引入严格求值：

1. seq 与严格应用符 ($!)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``seq`` 先把第一个参数求值到 **WHNF**\ ，再返回第二个参数：

.. code:: haskell

   seq :: a -> b -> b

``$!`` 是结合了 ``seq`` 的严格函数应用：

.. code:: haskell

   f $! x = x `seq` f x

2. 深度求值：Control.DeepSeq 与 ($!!)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``seq`` 只求值到 WHNF，对嵌套结构内部的 Thunk 无能为力。\ ``Control.DeepSeq`` 模块的 ``deepseq`` 与 ``$!!`` 通过 ``NFData`` 类型类把整个结构\ **递归求值到 NF**\ ：

.. code:: haskell

   import Control.DeepSeq

   -- 把嵌套结构完整求值：
   forcedResult = deepseq myList "计算完成"

3. BangPatterns 与严格字段
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

在函数参数或记录字段前加感叹号 ``!``\ ，指示编译器在进入函数体或构造数据时立即把它求值到 WHNF：

.. code:: haskell

   {-# LANGUAGE BangPatterns #-}

   -- 严格累加器，避免空间泄漏
   sumStrict :: Num a => a -> [a] -> a
   sumStrict !acc []     = acc
   sumStrict !acc (x:xs) = sumStrict (acc + x) xs

性能剖析与空间泄漏定位
--------------------------------------------------------------------------------

当程序内存占用异常上升时，可以用 GHC 自带的剖析工具定位问题。

第一步：开启剖析编译
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

使用 ``-prof`` 与 ``-fprof-auto`` 编译：

.. code:: sh

   $ ghc -prof -fprof-auto -rtsopts Main.hs -o myprog

- ``-prof``\ ：开启剖析信息收集。
- ``-fprof-auto``\ ：自动在所有顶层绑定处插入成本中心（Cost Centre）。
- ``-rtsopts``\ ：允许运行时通过 ``+RTS`` 传递参数。

如果是 Cabal 项目，用 ``cabal build --enable-profiling`` 即可，依赖库也会以剖析模式重新编译。

第二步：生成时间与分配报告
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

运行程序并附带 RTS 参数：

.. code:: sh

   $ ./myprog +RTS -p

运行结束后会在当前目录生成 ``myprog.prof``\ 。文件里列出每个成本中心占用的 **CPU 时间百分比** 与 **内存分配量**\ ，可以直接找到热点。

第三步：生成堆内存曲线
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

用 ``-hc`` 按成本中心采样堆内存：

.. code:: sh

   $ ./myprog +RTS -hc -p

运行完毕后生成 ``myprog.hp``\ 。用 GHC 自带的 ``hp2ps`` 转换成 PostScript 图：

.. code:: sh

   $ hp2ps -e8in -c myprog.hp

查看生成的 ``myprog.ps``\ ：

- **正常的堆**\ ：呈现规律的锯齿状（垃圾回收周期性回收内存）。
- **有空间泄漏的堆**\ ：呈现持续上升的斜坡。图中会标出是哪个成本中心在不断堆积数据，据此就能定位需要加严格性的位置。

小结
--------------------------------------------------------------------------------

- Haskell 采用按需调用，表达式只在被需要时求值一次，结果被共享。
- WHNF 只求值最外层构造器，NF 求值到底。
- ``seq``\ 、\ ``$!``\ 、\ ``deepseq`` 与 ``BangPatterns`` 用于在需要的位置引入严格性。
- ``-prof`` 配合 ``+RTS -p`` 和 ``-hc`` 可以定位时间热点和空间泄漏。
