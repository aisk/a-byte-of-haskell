函数式思维与 Lambda 演算
================================================================================

Haskell 是一门\ **纯函数式编程语言**\ 。要真正理解 Haskell 的设计哲学与代码表达方式，必须从它的数学根基——\ **Lambda 演算**\ （λ-calculus）出发。

什么是纯函数式编程？
--------------------------------------------------------------------------------

在传统的命令式语言（如 C、Python、Java）中，程序是一系列改变计算机内部状态的“指令”。而在纯函数式编程中：

1. **计算即表达式求值**\ ：程序由纯函数与表达式构成，执行程序就是不断对表达式求值的过程。
2. **纯函数（Pure Functions）**\ ：函数的输出完全由输入决定。相同的输入必定产生完全相同的输出。
3. **引用透明性（Referential Transparency）**\ ：任何表达式都可以直接用它的求值结果替换，而不会改变整个程序的运行行为。
4. **无隐式副作用（No Implicit Side Effects）**\ ：函数执行不会暗中修改全局变量、修改外部文件或更改入参状态。

这种纯粹性使得函数式代码极易进行数学推理、单元测试与无死锁并发扩展。

Lambda 演算的结构
--------------------------------------------------------------------------------

Lambda 演算是逻辑学家阿隆佐·邱奇（Alonzo Church）在 20 世纪 30 年代提出的形式系统，用来形式化研究函数定义、函数应用与递归。在 Lambda 演算的世界里，\ **一切计算皆为函数**\ 。

一个 Lambda 项仅由三部分递归构成：

- **变量（Variables）**\ ：例如 ``x``\ 、\ ``y``\ 。
- **抽象（Abstraction）**\ ：定义一个函数。由头部（head）和主体（body）构成。
  记作 ``λx.x``\ 。
  其中 ``λx`` 是头部，\ ``x`` 是形参；点号 ``.`` 之后的 ``x`` 是函数主体。
- **应用（Application）**\ ：将函数作用于某个参数。记作：\ ``(λx.x) y``\ 。

绑定变量与自由变量
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

观察函数 ``λx.xy``\ ：

- ``x`` 在头部被声明，被称为\ **绑定变量（Bound Variable）**\ 。
- ``y`` 未在头部出现，由外部环境决定，被称为\ **自由变量（Free Variable）**\ 。

三大核心约简与转换法则
--------------------------------------------------------------------------------

在 Lambda 演算中，计算的本质是项的\ **重写与约简（Reduction）**\ 。它由三条核心法则支配：

1. Alpha 转换（α-conversion）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Alpha 转换指出：\ **绑定变量的具体名称在语义上是无关紧要的**\ 。只要不引发命名冲突，重命名绑定变量不会改变函数的数学含义：

.. code:: text

   λx.x  =α=  λy.y  =α=  λz.z

当存在自由变量时，重命名必须保证\ **不捕获自由变量**\ （避免自由变量被意外转为绑定变量）：

.. code:: text

   -- 合法转换：
   λx.x y  =α=  λz.z y

   -- 非法转换（变量 y 被意外捕获）：
   λx.x y  ≠α  λy.y y

2. Beta 约简（β-reduction）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

当我们把一个实参传递给函数时，就发生了\ **β-约简**\ ：将函数体内部所有绑定变量替换为实参，并消除函数头部的形参声明。

恒等函数应用于值 ``2``\ ：

.. code:: text

   (λx.x) 2
   => 2

多参数与柯里化（Currying）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

在纯 Lambda 演算中，\ **每个函数严格只接受一个参数**\ 。那么多参数计算如何表达？

答案是通过函数的嵌套——每个函数接受一个参数，并返回另一个接受下一个参数的函数。这种机制被称为\ **柯里化（Currying）**\ 。

例如两数相加的函数：

.. code:: text

   λx.λy.x + y

连续传入参数的求值过程如下：

.. code:: text

   ((λx.λy.x + y) 1) 2
   => (λy.1 + y) 2
   => 1 + 2
   => 3

在 Haskell 中，所有函数本质上都遵守这一柯里化模型。

3. Eta 约简与展开（η-reduction）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Eta 约简表达了函数的外延等价性（Extensionality）：\ **如果两个函数对所有相同的输入都产生相同的输出，那么这两个函数就是完全相等的**\ 。

形式化记作：

.. code:: text

   λx.(f x)  =η=  f   （前提是 x 在 f 中不是自由变量）

例如，在 Haskell 中定义一个包装函数：

.. code:: haskell

   -- 显式传递参数：
   addOne x = (+ 1) x

   -- 经过 η-约简后消除参数（无点风格 Pointfree）：
   addOne = (+ 1)

这种无点风格在后续章节的代码管道重构中将展现出极强的表达力。

邱奇编码：一切皆函数
--------------------------------------------------------------------------------

为了直观体会“一切计算皆函数”，我们可以用纯粹的 Lambda 表达式构造出布尔逻辑与条件分支（邱奇布尔值，Church Booleans）：

.. code:: text

   TRUE  = λx.λy.x   -- 接收两个分支，返回第一个分支
   FALSE = λx.λy.y   -- 接收两个分支，返回第二个分支

基于这个定义，条件判断 ``IF-THEN-ELSE`` 可以直接定义为函数应用：

.. code:: text

   IF = λb.λthen.λelse.b then else

验证 ``IF TRUE A B`` 的约简：

.. code:: text

   IF TRUE A B
   => (λb.λthen.λelse.b then else) TRUE A B
   => TRUE A B
   => (λx.λy.x) A B
   => A

在纯 Lambda 演算中，无需内置任何原生的布尔类型或 ``if`` 关键字，纯粹的函数应用即可完整表达所有控制流逻辑。

求值策略与汇流性
--------------------------------------------------------------------------------

当一个表达式包含多个可以约简的子项（Redex）时，约简的先后顺序至关重要：

1. **应用序（Applicative Order / 严格求值）**\ ：在将实参传入函数主体之前，必须先将实参约简完毕（即主流语言的“按值调用”）。
2. **规范序（Normal Order / 非严格求值）**\ ：始终优先约简最外层的函数应用，仅在必要时才展开参数。

丘奇-罗瑟定理（Church-Rosser Theorem）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

定理指出：\ **Lambda 演算具有汇流性（Confluence）**\ 。如果一个项通过不同的约简路径最终都能约简到不能再约简的形式（范式），那么这两种路径得到的最终结果必定在 α-等价意义下是完全相同的。

更重要的是：\ **如果一个表达式存在可终止的范式，规范序约简一定能够找到它，而应用序则可能会陷入死循环**\ 。这就是 Haskell 坚持采用非严格求值（惰性求值）的核心理论支撑。

范式与发散
--------------------------------------------------------------------------------

Beta 范式（Beta Normal Form）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

当一个 Lambda 项经过若干次约简，不再包含任何可以继续应用的函数项时，该项就达到了\ **Beta 范式**\ （即计算完成的最终值）。

发散（Divergence）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

并非所有表达式都能约简至范式。考虑著名的 Ω 组合子：

.. code:: text

   (λx.x x) (λx.x x)

对其进行约简：将实参 ``(λx.x x)`` 代入形参 ``x`` 中，得到的依然是：

.. code:: text

   (λx.x x) (λx.x x)

无论约简多少步，表达式永远无法停机并得到最终结果。在编程语言中，这种死循环或无法完成求值的情况被称为\ **发散（Divergence）**\ 。在 Haskell 中，这种概念被抽象为\ **底（Bottom，记作 ⊥）**\ 。

小结
--------------------------------------------------------------------------------

- Haskell 建立在严格的 Lambda 演算基础之上，计算即表达式的约简与替换。
- α-转换保障变量命名解耦，β-约简推动计算前行，η-约简奠定了无点风格的数学基础。
- 纯 Lambda 演算足以表达布尔逻辑、数字与所有控制流。
- 规范序求值的停机保证为 Haskell 的惰性求值奠定了不可动摇的理论基石。
