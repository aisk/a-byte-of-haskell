函子（Functor）与范畴映射
================================================================================

在实际编程中，数据极少是裸露存在的，通常被包裹在某种\ **上下文（Context）**\ 中——例如可能为空的 ``Maybe a``\ 、包含多个元素的列表 ``[a]``\ 、携带错误信息的 ``Either e a``\ 、或是包含输入环境的函数 ``r -> a``\ 。

**函子（Functor）**\ 是函数式编程中最重要的抽象基石之一，它定义了如何将一个普通的纯函数，无侵入地“提升”（Lift）到各种上下文中并对内部的值执行映射。

Functor 的形式化定义
--------------------------------------------------------------------------------

定义在标准库中：

.. code:: haskell

   class Functor f where
     fmap :: (a -> b) -> f a -> f b

   (<$>) :: Functor f => (a -> b) -> f a -> f b
   (<$>) = fmap

- 注意 ``f`` 的 Kind 必须是 ``* -> *``\ ，即它必须是一个单参数的\ **类型构造器**\ 。
- ``fmap`` 接收一个纯函数 ``(a -> b)`` 与一个处在上下文中的值 ``f a``\ ，返回变换后的新上下文 ``f b``\ 。
- 中缀操作符 ``<$>`` 是 ``fmap`` 的常用同义词，它在视觉上与函数应用符 ``$`` 对齐。

.. tip::

   **心智模型突破：把 Functor 理解为 “Mappable”**\ ：

   初学者常被“函子（Functor）”这一高深的范畴论数学名词所震慑。但在日常工程实践中，你可以直接将 Functor 直观理解为 ``Mappable``\ （可执行映射变换的上下文/容器）。

   - **通俗直觉**\ ：只要一种数据结构或计算上下文包装了值，并且它允许你\ **传入一个普通纯函数作用于内部的值，同时保持外层包装结构不变**\ ，它就是 Functor。
   - **跨语言映射**\ ：
     - **JavaScript / TypeScript**\ ：数组的 ``[].map(...)``\ 、\ ``Promise.then(...)`` （仅针对纯变换时）。
     - **Java**\ ：\ ``Stream.map(...)``\ 、\ ``Optional.map(...)``\ 、\ ``CompletableFuture.thenApply(...)``\ 。
     - **Rust**\ ：\ ``Option::map(...)``\ 、\ ``Result::map(...)``\ 、\ ``Iterator::map(...)``\ 。
     - **Python**\ ：列表推导式 ``[f(x) for x in xs]`` 或内置的 ``map(f, xs)``\ 。
   - **严谨性说明**\ ：虽然从严格的范畴论定义来看，Functor 是保持对象与态射结构的范畴映射，且并非所有 Functor 都是物理数据容器（例如函数类型 ``(->) r`` 也是合法的 Functor，它代表计算流水线的后处理映射），**但将 Functor 理解为“支持 map 的抽象上下文（Mappable）”是扫清初学认知障碍、极速建立工程直觉的极佳心智模型**。

常用辅助操作符：<$、$> 与 void
--------------------------------------------------------------------------------

除了基础的 ``fmap``\ ，标准库 ``Data.Functor`` 还提供了一系列在日常开发中极其实用的组合操作符：

保持结构替换值：<$ 与 $>
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- ``(<$) :: Functor f => a -> f b -> f a``\ ：将上下文中的所有值替换为左侧的常量，同时\ **完全保留外层结构的外形**\ 。
- ``($>) :: Functor f => f a -> b -> f b``\ ：同上，只是参数顺序调换。

.. code:: text

   ghci> import Data.Functor
   ghci> 0 <$ [1, 2, 3, 4]
   [0,0,0,0]

   ghci> "OK" <$ Just 123
   Just "OK"

   ghci> "OK" <$ Nothing
   Nothing

清空内容只留效果：void
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. code:: haskell

   void :: Functor f => f a -> f ()
   void x = () <$ x

``void`` 将上下文内部的值彻底丢弃，替换为 Unit 类型 ``()``\ 。在并发编程和文件 I/O 中，当你不关心操作的返回值、只关心其副作用是否执行完毕时，\ ``void`` 是最高频使用的标准惯用法：

.. code:: haskell

   -- 读取一行文本，但丢弃内容，只触发控制台读取动作：
   clearOneLine :: IO ()
   clearOneLine = void getLine

标准库典型 Functor 实例
--------------------------------------------------------------------------------

1. 列表：批量无损映射
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

列表的 ``fmap`` 就是我们熟知的 ``map``\ ：

.. code:: text

   ghci> (* 2) <$> [1, 2, 3]
   [2,4,6]

2. Maybe：安全条件执行
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

只在有值时映射；为 ``Nothing`` 时自动传递缺失：

.. code:: text

   ghci> (+ 10) <$> Just 5
   Just 15
   ghci> (+ 10) <$> Nothing
   Nothing

3. Either e：仅作用于成功分支
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

由于 ``Either`` 的 Kind 是 ``* -> * -> *``\ ，必须先部分应用左侧错误类型，得到 ``Either e``\ （Kind 为 ``* -> *``\ ）：

.. code:: text

   ghci> (+ 1) <$> (Right 41 :: Either String Int)
   Right 42
   ghci> (+ 1) <$> (Left "超时" :: Either String Int)
   Left "超时"

4. 函数也是 Functor：函数管道的胚胎
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

函数类型构造器 ``(->) r`` 是一个合法的 Functor！对函数执行 ``fmap`` 实际上就是\ **函数组合**\ ：

.. code:: haskell

   instance Functor ((->) r) where
     fmap = (.)

.. code:: text

   -- 管道：先乘以 2，再加 1
   ghci> pipeline = (+ 1) <$> (* 2)
   ghci> pipeline 10
   21

为自定义类型实现与自动派生 Functor
--------------------------------------------------------------------------------

手动为自定义树结构实现 Functor：

.. code:: haskell

   data Tree a
     = Leaf a
     | Node (Tree a) (Tree a)
     deriving (Show, Eq)

   instance Functor Tree where
     fmap f (Leaf x)   = Leaf (f x)
     fmap f (Node l r) = Node (fmap f l) (fmap f r)

利用 GHC 语言扩展自动派生
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

借助 ``DeriveFunctor`` 语言扩展，我们无需手动编写重复的结构遍历样板：

.. code:: haskell

   {-# LANGUAGE DeriveFunctor #-}

   data Tree a
     = Leaf a
     | Node (Tree a) (Tree a)
     deriving (Show, Eq, Functor)  -- 编译器自动安全生成 fmap 代码

双函子：Data.Bifunctor
--------------------------------------------------------------------------------

对于拥有两个类型参数的容器（如二元组 ``(,)`` 与 ``Either``\ ），标准库 ``Data.Bifunctor`` 提供了同时或分别变换两侧能力的 ``Bifunctor``\ ：

.. code:: haskell

   import Data.Bifunctor

   -- bimap :: (a -> b) -> (c -> d) -> p a c -> p b d
   -- first :: (a -> b) -> p a c -> p b c
   -- second :: (b -> c) -> p a b -> p a c

.. code:: text

   ghci> bimap (* 2) reverse (10, "hello")
   (20,"olleh")

   ghci> first (++ "错误: ") (Left "404" :: Either String Int)
   Left "404错误: "

Functor 两大法则（Laws）
--------------------------------------------------------------------------------

任何合法的 Functor 必须严格遵守以下两条数学定律：

1. 同一律（Identity）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

对上下文映射恒等函数 ``id``\ ，结果必须与原上下文完全相同：

.. code:: text

   fmap id == id

2. 复合律（Composition）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

连续两次映射函数 ``g`` 与 ``f``\ ，必须严格等价于一次性映射它们的复合函数 ``(f . g)``\ ：

.. code:: text

   fmap (f . g) == fmap f . fmap g

**定律的深层工程意义**\ ：
Functor 的法则向程序员提供了一个铁一般的契约保证：\ **fmap 仅仅且只能变换容器内部的值，严禁改变外层结构的结构外形、大小或元数据**\ （例如，\ ``fmap`` 绝不允许在转换过程中丢弃列表中的元素或反转列表）。

小结
--------------------------------------------------------------------------------

- ``Functor`` 定义了在上下文内部映射纯函数的通用能力。
- 善用 ``<$>``\ 、\ ``<$`` 与 ``void`` 提升代码的紧凑度与表现力。
- ``(->) r`` 作为 Functor 揭示了上下文映射与函数复合的内在同一性。
- 通过 ``DeriveFunctor`` 自动化实现实例，用 ``Bifunctor`` 轻松应对双通道容器。
- 严格遵循同一律与复合律，保证上下文结构在映射过程中稳定不变。
